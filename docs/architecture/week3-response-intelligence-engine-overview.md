# Week 3: Response Intelligence Engine Overview

## 1. Introduction

The **Response Intelligence Engine** represents Cognis' analytical capability to observe, reconstruct, and comprehend the outputs generated by AI platforms (e.g., ChatGPT). Unlike the Enrichment Engine, which modifies outgoing prompts, this engine acts purely as an observer on incoming data streams. 

Crucially, **this engine does not generate insights.** Its sole responsibility is to analyze a *single* response in isolation, evaluate it across multiple dimensions (structure, reasoning, completeness, and quality), and emit a standardized, deterministic metric event (`response.analysis.completed`). These events are later synthesized longitudinally by the Insight Engine.

## 2. Architectural Highlights

### Transient Transport Data Policy (ADR-019)
A core challenge of this engine is that analyzing reasoning and structure requires access to the raw response text. However, Section 2 of the Engineering Constitution strictly prohibits persisting conversational data.

To solve this, we introduced the **Transient Transport Data Policy (ADR-019)**:
- `chunkText` is added to the EventBus payload strictly as `[TRANSPORT-ONLY]`.
- The text exists purely in volatile memory.
- The `EventStoreSubscriber` explicitly sanitizes and strips the text before appending events to IndexedDB.
- The in-memory buffer is forcibly dereferenced and garbage collected the millisecond the analysis completes.

### Deterministic Analyzer Contracts
The engine's analysis is split into pure, deterministic heuristics. The `ResponseAnalyzer` contract guarantees that analyzers process text without side effects, outputting a normalized `AnalysisResult`.
1. **StructureAnalyzer**: Evaluates code blocks, headers, lists, and markdown density.
2. **ReasoningAnalyzer**: Detects step-by-step logic chains ("because", "therefore") and branching logic ("alternatively", "however").
3. **CompletenessAnalyzer**: Detects abrupt cutoffs and unclosed markdown tags.
4. **QualityAnalyzer**: A composite orchestrator that aggregates sub-analyzer scores.

### Buffer Orchestration
The `ReconstructorBuffer` is designed for safety and privacy:
- Supports concurrent browser tabs (keyed by `sessionId`).
- Strict 500KB limit per session to prevent OOM errors.
- 60-second inactivity watchdog timeout to discard zombie buffers.

## 3. CQRS Boundary

The Response Intelligence Engine strictly adheres to CQRS boundaries. It listens to `ResponseEvents` (Command side) and emits factual observations. It does not update Projections or write to the database. Its output (`response.analysis.completed`) becomes the input for Projection Builders, maintaining clean separation of concerns.
